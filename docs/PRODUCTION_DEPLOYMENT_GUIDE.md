## Why Simulation is FORBIDDEN in Production

### Critical Reasons:

1. **Data Integrity**: Simulated data (LP="SIM") would corrupt production databases
2. **Client Trust**: Clients must receive ONLY real market data from actual liquidity providers
3. **Regulatory Compliance**: Financial regulations require real, traceable market data
4. **Business Logic**: Trading decisions based on fake data could cause financial losses
5. **Audit Trail**: Regulatory audits require authentic data sources

### What is Simulation Data?

Simulation data is:
- Market ticks with `lp_source = 'SIM'` or `lp_source = 'SIMULATION'`
- Generated by internal algorithms (not real liquidity providers)
- Used ONLY in development/testing environments
- **NEVER ACCEPTABLE** in production

## Multi-Layer Safeguards

### Layer 1: Environment Variables

```bash
# .env file for PRODUCTION
ENVIRONMENT=production
ALLOW_SIMULATION=false  # MUST be false or unset

# These MUST NOT be set in production
SIMULATION_MODE=        # MUST be empty
```

**Validation**: Server will panic on startup if `ALLOW_SIMULATION=true` in production.

### Layer 2: Build Tags (Compile-Time Prevention)

Create simulation code with build tag:

```go
// +build !production

package simulation

func GenerateSimulatedTicks() {
    // This code will NOT compile in production builds
}
```

**Production build command**:
```bash
go build -tags production -o server ./cmd/server
```

### Layer 3: Runtime Checks

```go
// In main.go startup
func main() {
    // CRITICAL: Validate production environment
    cfg, err := config.Load()
    if err != nil {
        log.Fatalf("Failed to load config: %v", err)
    }

    // Production validation - FAILS if simulation detected
    if cfg.Environment == "production" {
        validator := config.NewProductionValidator(cfg)
        if err := validator.ValidateProduction(); err != nil {
            log.Fatalf("PRODUCTION VALIDATION FAILED: %v", err)
        }
    }

    // Continue only if validation passes...
}
```

### Layer 4: Database Constraints

```sql
-- Add constraint to prevent simulation data
ALTER TABLE ticks
ADD CONSTRAINT no_simulation_in_production
CHECK (
    (current_setting('app.environment') != 'production')
    OR
    (lp_source != 'SIM' AND lp_source != 'SIMULATION')
);

-- Set environment in database connection
SET app.environment = 'production';
```

### Layer 5: Monitoring & Alerts

See [Monitoring & Alerts](#monitoring--alerts) section below.

## Pre-Deployment Checklist

### Before deploying to production, verify:

- [ ] **Environment Variables Set Correctly**
  ```bash
  ENVIRONMENT=production
  ALLOW_SIMULATION=false
  ```

- [ ] **Real LP Credentials Configured**
  - [ ] YOFX FIX sessions (YOFX_HOST, YOFX_PORT, credentials)
  - [ ] OR OANDA API (OANDA_API_KEY, OANDA_ACCOUNT_ID)
  - [ ] OR Binance API (BINANCE_API_KEY, BINANCE_SECRET_KEY)

- [ ] **Security Settings**
  - [ ] JWT_SECRET set (min 32 characters)
  - [ ] ADMIN_PASSWORD_HASH set
  - [ ] MASTER_ENCRYPTION_KEY set (min 32 characters)

- [ ] **Database Configuration**
  - [ ] PostgreSQL connection working
  - [ ] SSL enabled (DB_SSL_MODE != "disable")
  - [ ] Migrations applied

- [ ] **Build Configuration**
  - [ ] Built with production tag: `go build -tags production`
  - [ ] Simulation code excluded from binary

- [ ] **Monitoring**
  - [ ] Prometheus/Grafana configured
  - [ ] Alerts configured for simulation detection
  - [ ] Health check endpoints working

### Automatic Validation on Startup

```

[ProductionValidator] ✓ YOFX FIX LP configured
[ProductionValidator] ✓ No simulation data found in ticks table
[ProductionValidator] Liquidity provider distribution:
  - YOFX: 1,234,567 ticks
  - OANDA: 456,789 ticks
[ProductionValidator] ✓ All production validation checks passed
```

### Validation Checks Performed

1. **Environment Check**: `ENVIRONMENT=production`
2. **Simulation Disabled**: `ALLOW_SIMULATION` not set or `false`
3. **Real LP Configured**: At least one real liquidity provider
4. **Security Settings**: JWT secret, encryption key, admin password
5. **Database Scan**: No simulation data in ticks table
6. **FIX Configuration**: FIX sessions configured (if using YOFX)

## Data Source Verification

### Health Check Endpoint

```bash
GET /admin/health/data-source
```

**Returns**:
- `status: "healthy"` - No simulation data, real LP data flowing
- `status: "degraded"` - Warnings but no critical issues
- `status: "critical"` - Simulation data detected (HTTP 500)

### Simulation Report Endpoint

```bash
GET /admin/data-source/simulation-report
```

Shows detailed breakdown of any simulation data found.

### Cleanup Endpoint (Tag Simulation Data)

```bash
POST /admin/data-source/cleanup
Content-Type: application/json

{
  "dryRun": true
}
```

**Dry Run**: Shows what would be tagged
**Live Run**: Tags simulation data with `flags |= 1` for identification

**NOTE**: Does NOT delete data, only tags it for audit trail.

## Monitoring & Alerts

### Metrics to Track

1. **market_data_source_type**
   - Gauge: 0 = simulation, 1 = real
   - Alert if value is 0 in production

2. **ticks_by_lp_source**
   - Counter by LP source
   - Alert if "SIM" counter increments

3. **data_freshness_seconds**
   - Age of latest tick
   - Alert if > 300 seconds (5 minutes)

### Prometheus Alerts

```yaml
# prometheus-alerts.yml
groups:
  - name: trading_engine_production
    rules:
      - alert: SimulationDataDetected
        expr: market_data_source_type == 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "CRITICAL: Simulation data detected in production"
          description: "Simulation market data is running in production environment"

      - alert: SimulationTicksInDatabase
        expr: ticks_by_lp_source{lp_source="SIM"} > 0
        for: 1m
        labels:
          severity: critical
        annotations:
          summary: "CRITICAL: Simulation ticks found in production database"
          description: "Found {{ $value }} simulation ticks in production database"

      - alert: MarketDataStale
        expr: data_freshness_seconds > 300
        for: 5m
        labels:
          severity: warning
        annotations:
          summary: "Market data is stale"
          description: "No market data received for {{ $value }} seconds"

      - alert: NoRealLPData
        expr: sum(rate(ticks_by_lp_source{lp_source!="SIM"}[5m])) == 0
        for: 10m
        labels:
          severity: critical
        annotations:
          summary: "No real LP data flowing"
          description: "No ticks received from real liquidity providers"
```

### Grafana Dashboard

Create panels for:
1. **LP Source Distribution** (pie chart)
2. **Tick Rate by LP** (time series)
3. **Data Freshness** (gauge)
4. **Simulation Alert** (stat panel, red if detected)

## Emergency Procedures

### If Simulation Detected in Production

**IMMEDIATE ACTIONS**:

1. **STOP THE SERVER**
   ```bash
   systemctl stop trading-engine
   # or
   docker stop trading-engine
   ```

2. **Verify the Alert**
   ```bash
   # Check database
   psql trading_engine -c "SELECT COUNT(*) FROM ticks WHERE lp_source = 'SIM';"
   ```

3. **Identify the Cause**
   - Check environment variables
   - Review recent deployments
   - Check server logs for simulation initialization

4. **Tag Affected Data**
   ```bash
   curl -X POST http://localhost:7999/admin/data-source/cleanup \
     -H "Content-Type: application/json" \
     -d '{"dryRun": false}'
   ```

5. **Fix Configuration**
   ```bash
   # Ensure correct environment
   export ENVIRONMENT=production
   export ALLOW_SIMULATION=false
   unset SIMULATION_MODE
   ```

6. **Verify Real LP Configuration**
   ```bash
   # Check .env file
   grep -E "YOFX|OANDA|BINANCE" .env

   # Verify credentials are set
   echo $YOFX_HOST
   echo $OANDA_API_KEY
   ```

7. **Rebuild with Production Tag**
   ```bash
   go build -tags production -o server ./cmd/server
   ```

8. **Re-validate Before Restart**
   ```bash
   # Run validation script
   ./scripts/validate-production.sh
   ```

9. **Monitor Closely After Restart**
   ```bash
   # Watch health endpoint
   watch -n 5 curl -s http://localhost:7999/admin/health/data-source | jq .

   # Watch logs
   tail -f /var/log/trading-engine/server.log | grep -i sim
   ```

10. **Document Incident**
    - Create incident report
    - Root cause analysis
    - Update procedures to prevent recurrence

## Deployment Scripts

### Production Deployment Script

```bash
#!/bin/bash
# deploy-production.sh

set -e

echo "=== Trading Engine Production Deployment ==="

# 1. Verify environment
if [ "$ENVIRONMENT" != "production" ]; then
    echo "ERROR: ENVIRONMENT must be set to 'production'"
    exit 1
fi

# 2. Check for simulation flags
if [ "$ALLOW_SIMULATION" == "true" ]; then
    echo "ERROR: ALLOW_SIMULATION must be false or unset"
    exit 1
fi

# 3. Verify LP credentials
if [ -z "$YOFX_HOST" ] && [ -z "$OANDA_API_KEY" ] && [ -z "$BINANCE_API_KEY" ]; then
    echo "ERROR: No real LP configured. Set YOFX, OANDA, or Binance credentials."
    exit 1
fi

# 4. Build with production tag
echo "Building with production tag..."
go build -tags production -ldflags="-s -w" -o bin/server ./cmd/server

# 5. Run tests
echo "Running production safety tests..."
go test -tags production ./...

# 6. Verify binary doesn't contain simulation code
if strings bin/server | grep -i "GenerateSimulatedTicks"; then
    echo "ERROR: Binary contains simulation code!"
    exit 1
fi

# 7. Deploy
echo "Deploying to production..."
# Your deployment commands here

echo "=== Deployment Complete ==="
echo "Monitor: /admin/health/data-source"
```

## Summary

### Golden Rules for Production

1. ✅ **ONLY real liquidity providers** (YOFX, OANDA, Binance)
2. ✅ **ENVIRONMENT=production** always set
3. ✅ **ALLOW_SIMULATION=false** or unset
4. ✅ **Build with production tag**: `go build -tags production`
5. ✅ **Monitor health endpoint**: `/admin/health/data-source`
6. ✅ **Alert on simulation detection**: Critical severity
7. ✅ **Regular database scans**: Check for LP='SIM'
8. ✅ **Audit trail**: Tag but don't delete simulation data if found
